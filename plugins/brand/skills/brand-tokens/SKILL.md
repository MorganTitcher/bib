# Brand tokens

The single source of truth is `packages/tokens/tokens/brand.tokens.json`, in the W3C Design Tokens (DTCG 2025.10) format. Everything else is generated by Terrazzo. Never hand-edit files in `packages/tokens/build/`.

## Edit

- Each token has `$type` and `$value`; add a `$description` that says where it is used.
- Colors use the object form: `{ "colorSpace": "oklch", "components": [L, C, H] }`.
- Prefer aliases (`"{color.neutral.900}"`) for semantic tokens such as `color.surface.*`, so a palette change flows through.
- Dimensions are `{ "value": 8, "unit": "px" }`.

## Build and check

```sh
pnpm --filter @bib/tokens test   # terrazzo check: schema and alias validation
pnpm --filter @bib/tokens build  # writes build/tokens.css, build/tokens.js, build/tokens.d.ts
```

## Use

- CSS: `@import "@bib/tokens/css";` then `var(--bib-color-brand-primary)`. Variable names are the token path with dots replaced by dashes, prefixed `--bib-`.
- JS/TS: `import { resolver } from "@bib/tokens";` then `resolver.apply({})["color.brand.primary"]` for typed, normalized values.
- Raw source: `@bib/tokens/source` for tools that read DTCG directly.

The example brand ships 21 tokens in one mode. There are no dark-mode or per-brand themes yet, so do not invent a theme structure. Say it is missing.

After changing a token, rebuild and check contrast for any text-on-surface pair you touched (WCAG AA: 4.5:1 for body text, 3:1 for large text). Use the package rather than eyeballing it. `contrastRatio` accepts oklch strings:

```sh
cd packages/svg && node --input-type=module -e 'import { contrastRatio } from "@bib/svg/color"; console.log(contrastRatio("oklch(20% 0.016 260)", "oklch(99% 0.003 260)").toFixed(2))'
```
